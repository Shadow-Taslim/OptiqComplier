# Express ↔ C++ Compiler JSON Contract

**Contract version:** `1.0`  
**Status:** Week 1 definition; implementation starts in a later week.

## Transport Rules

- Express exposes `POST /api/compile` and `POST /api/execute`, mapping them to compiler operations `compile` and `execute`.
- Express starts one compiler process per operation and writes exactly one UTF-8 JSON object to stdin.
- The compiler writes exactly one JSON response object to stdout. Diagnostics may go to stderr but must never corrupt stdout.
- `requestId` is generated by Express and echoed unchanged for log correlation.
- `catalog` is an allow-listed catalog identifier, initially only `sample-v1`; it is never a user-supplied path.
- `compile` performs lexing, parsing, semantic analysis, planning, and optional optimization. It does not read result rows.
- `execute` performs the same steps and then runs the optimized plan, subject to the row and time limits.

## Request

```json
{
  "contractVersion": "1.0",
  "requestId": "0f4b2dd1-47b7-4bb0-a96f-f7bb53ac7e52",
  "operation": "execute",
  "catalog": "sample-v1",
  "sql": "SELECT name FROM employees;",
  "options": {
    "optimize": true,
    "maxRows": 100,
    "timeoutMs": 2000
  }
}
```

| Field | Type | Required | Rules |
| --- | --- | --- | --- |
| `contractVersion` | string | yes | Must be `"1.0"`. |
| `requestId` | string | yes | Non-empty correlation ID generated by Express. |
| `operation` | string | yes | `"compile"` or `"execute"`. |
| `catalog` | string | yes | Initially `"sample-v1"`. |
| `sql` | string | yes | One SQL statement; Express rejects empty input. |
| `options` | object | no | Defaults shown in the example. |
| `options.optimize` | boolean | no | Default `true`; `false` executes the initial plan. |
| `options.maxRows` | integer | no | Execute only; range 1–1000, default 100. |
| `options.timeoutMs` | integer | no | Execute only; range 1–10000, default 2000. |

Unknown request fields are ignored for forward compatibility. Missing or invalid required fields produce `INVALID_REQUEST`.

## Common Response Envelope

Every completed operation uses the same top-level shape:

| Field | Success value | Error value |
| --- | --- | --- |
| `contractVersion` | `"1.0"` | `"1.0"` |
| `requestId` | Echo of request | Echo of request, or `null` if unreadable |
| `operation` | Requested operation | Requested operation, or `null` if unreadable |
| `ok` | `true` | `false` |
| `plans` | Initial and optimized plan trees | Available partial trees, otherwise nulls |
| `optimizations` | Applied optimization records | Records completed before failure, usually `[]` |
| `result` | Result object for execute; `null` for compile | `null` |
| `statistics` | Timing, row, plan, and optimizer counters | Measurements available at failure |
| `error` | `null` | Structured error object |

### Plan Nodes

Both `plans.initial` and `plans.optimized` are either `null` or a recursive node:

```json
{
  "id": "p1",
  "operator": "Selection",
  "properties": {
    "predicate": "salary > 70000"
  },
  "children": []
}
```

- `id` is unique within one plan tree.
- `operator` is one of `TableScan`, `Projection`, `Selection`, `Join`, `Aggregate`, `Sort`, or `Limit`.
- `properties` contains operator-specific JSON values such as `table`, `columns`, `predicate`, `condition`, `aggregates`, `groupBy`, `orderBy`, or `count`.
- `children` is an array: zero for scans, one for unary operators, and two for joins.

Each entry in `optimizations` has this shape:

```json
{
  "type": "CONSTANT_FOLDING",
  "description": "Folded 50000 + 20000 to 70000.",
  "before": "salary > 50000 + 20000",
  "after": "salary > 70000"
}
```

Allowed `type` values are `PREDICATE_PUSHDOWN`, `PROJECTION_PRUNING`, and `CONSTANT_FOLDING`. `before` and `after` may be `null` when a textual fragment is not meaningful.

### Result

`result` is non-null only for successful execute responses:

```json
{
  "columns": [
    { "name": "name", "type": "text", "table": "employees" }
  ],
  "rows": [
    ["Aisha Rahman"]
  ],
  "rowCount": 1,
  "truncated": false
}
```

Rows are arrays aligned with `columns`; values are JSON strings, numbers, booleans, or `null`. `rowCount` is the number of returned rows. If execution stops at `maxRows`, `truncated` is `true`. Column `table` is `null` for computed expressions.

### Statistics

```json
{
  "timingsMs": {
    "lexParse": 0.31,
    "semantic": 0.08,
    "plan": 0.05,
    "optimize": 0.04,
    "execute": 0.72,
    "total": 1.20
  },
  "rows": {
    "scanned": 1,
    "returned": 1
  },
  "planNodes": {
    "initial": 3,
    "optimized": 3
  },
  "optimizations": {
    "predicatePushdowns": 0,
    "projectionsPruned": 0,
    "constantsFolded": 0
  }
}
```

Timing values are non-negative numbers. `execute` is `null` for compile operations. Row counts are zero for compile operations. All counters are integers.

## Errors

```json
{
  "contractVersion": "1.0",
  "requestId": "44d1c20e-52c8-44ed-bbb3-76ac2d5ea947",
  "operation": "compile",
  "ok": false,
  "plans": { "initial": null, "optimized": null },
  "optimizations": [],
  "result": null,
  "statistics": {
    "timingsMs": {
      "lexParse": 0.20,
      "semantic": 0.04,
      "plan": null,
      "optimize": null,
      "execute": null,
      "total": 0.24
    },
    "rows": { "scanned": 0, "returned": 0 },
    "planNodes": { "initial": 0, "optimized": 0 },
    "optimizations": {
      "predicatePushdowns": 0,
      "projectionsPruned": 0,
      "constantsFolded": 0
    }
  },
  "error": {
    "code": "UNKNOWN_TABLE",
    "stage": "semantic",
    "message": "Table 'missing_table' does not exist in catalog 'sample-v1'.",
    "location": { "line": 1, "column": 18, "offset": 17 },
    "details": { "table": "missing_table" }
  }
}
```

`location` is `null` when no SQL position applies. `details` is always an object and may be empty.

| Code | Typical stage | Meaning |
| --- | --- | --- |
| `INVALID_REQUEST` | `request` | Malformed JSON, missing fields, or invalid options. |
| `SQL_SYNTAX_ERROR` | `lex` or `parse` | Invalid token or grammar error. |
| `UNKNOWN_TABLE` | `semantic` | Referenced table is absent. |
| `UNKNOWN_COLUMN` | `semantic` | Referenced column is absent or ambiguous. |
| `TYPE_MISMATCH` | `semantic` | Operator or aggregate types are incompatible. |
| `UNSUPPORTED_SQL` | `parse` or `semantic` | Valid-looking SQL outside the declared subset. |
| `EXECUTION_ERROR` | `execute` | CSV, catalog, or runtime execution failure. |
| `TIMEOUT` | `execute` | Operation exceeded `timeoutMs`. |
| `ROW_LIMIT_EXCEEDED` | `execute` | Reserved for strict limits; normal `maxRows` truncation is not an error. |
| `INTERNAL_ERROR` | `internal` | Unexpected compiler failure without unsafe internals in `message`. |

Express returns HTTP 200 for successful operations, 400 for invalid requests, 422 for SQL/semantic errors, 504 for timeouts, and 500 for unexpected process or internal failures. The JSON envelope remains the primary payload in each case.
